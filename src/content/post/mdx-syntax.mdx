MDX 可以理解为 Markdown 加上 JSX。这篇文章本身就是 `.mdx`，和普通文章共用 frontmatter、列表页、RSS 与搜索，只是正文可以写 JSX、导入组件。

## 表达式

`{...}` 在构建期求值：

```mdx
这篇文档构建于 {new Date().toLocaleDateString('zh-CN')}。
```

渲染出来是：这篇文档构建于 {new Date().toLocaleDateString('zh-CN')}。

它不会随访客的时钟变化，也不能直接访问 `window`；需要交互时用客户端组件。

## 图片

图片仍用 Markdown 语法，规则与 `.md` 一致：

![MDX 示例图片](/images/demo/diary-line.svg)

需要显式图注或构建期优化时，用 `@ui` 的 `Figure`：

```mdx
import { Figure } from '@ui';
import cover from './cover.jpg';

<Figure src={cover} alt="山脊上的日落" caption="图注可选" />
```

## 组件与水合

把 `CurrentDate.tsx`（每秒更新时间的 React 组件）放在文章旁边，然后在 `.mdx` 里导入：

```mdx guide.mdx
import CurrentDate from './CurrentDate';

现在是 <CurrentDate client:load />。
```

常用指令：`client:load`（立即）、`client:idle`（空闲时）、`client:visible`（进入视口时）、`client:only="react"`（仅浏览器）。不写指令时只有静态 HTML，没有交互。

实际效果：现在是 <CurrentDate client:load />。

## 文件位置

文章放 `src/content/post/`，日记放 `src/content/daily/`，独立页面放 `src/content/pages/`（由 `src/pages/[...page].astro` 自动套 `PageLayout`，不需要 `layout`）。子目录会保留在 slug 里。

## 与 `.md` 的边界

| 能力 | `.md` | `.mdx` |
| --- | --- | --- |
| frontmatter、列表、RSS、搜索 | 支持 | 支持 |
| 指令、图片、脚注等扩展 | 支持 | 支持 |
| 组件、JSX、表达式 | 不支持 | 支持 |
| `password` 加密 | 支持 | 不支持 |

`.mdx` 写了 `password` 会构建报错；需要加密请改用 `.md`。`rss.fullText` 为 `true` 时，MDX 文章在 RSS 里回退为摘要。
