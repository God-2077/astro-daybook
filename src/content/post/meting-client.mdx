import { meting } from '@mdx';

`@mdx` 暴露了 `meting.fetchMusic()` 与 `meting.player()`：前者在构建期取数据，后者默认在浏览器端取数（传 `client: false` 可改回构建期）。构建期示例只记录写法，页面构建时不请求 Meting-API；末尾的客户端播放器则在浏览器里加载曲目。

## 歌曲信息

`fetchMusic({ type: 'song' })` 返回单个曲目对象：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | `string` | 歌名 |
| `artist` | `string` | 歌手 |
| `album` | `string` | 专辑 |
| `source` | `string` | 音源，如 `netease` |
| `url` | `string` | 播放地址 |
| `pic` / `cover` | `string` | 封面地址，两者相同 |
| `lrc` | `string` | 歌词地址 |
| `raw` | `object` | 接口返回的原始字段 |

```mdx
import { meting } from '@mdx';

export const song = await meting.fetchMusic({
  server: 'netease',
  type: 'song',
  id: '1969519579',
});

歌名：{song.name}
歌手：{song.artist}
```

## 歌词

`type: 'lrc'` 返回纯文本，不是 JSON；取到后可以直接放进 `<pre>`：

```mdx
export const lyrics = await meting.fetchMusic({
  server: 'netease',
  type: 'lrc',
  id: '1969519579',
});

<pre>{lyrics.split(/\r?\n/).slice(0, 12).join('\n')}</pre>
```

## 播放器

`meting.player()` 会把查询渲染成 `MusicPlayer`，参数与 `fetchMusic` 一致，另加播放器选项；下面的例子显式传 `client: false`，在构建期取数：

```mdx
{await meting.player({
  server: 'netease',
  type: 'song',
  id: '1969519579',
  client: false,
  autoPlayNext: false,
  playlistExpand: false,
})}
```

`playlist`、`albumlist` 与 `search` 会渲染成曲目列表。

## 客户端播放器

`client` 默认为 `true`，构建期不再请求接口，改由浏览器取数据；下面的写法与省略 `client` 一致：

```mdx
{await meting.player({
  server: 'netease',
  type: 'playlist',
  id: '8900628861',
  autoPlayNext: true,
  playlistExpand: true,
})}
```

下面这个就是默认的客户端模式，曲目在浏览器里加载：

{await meting.player({
  server: 'netease',
  type: 'playlist',
  id: '8900628861',
  autoPlayNext: true,
  playlistExpand: false,
})}

浏览器端的接口地址与超时来自 `siteConfig.mdx.meting`，也可以用单次调用的 `api` / `timeout` 覆盖。

## 说明

- 构建期调用（上方的 `fetchMusic` 与显式 `client: false` 的 `player` 示例）会向 `siteConfig.mdx.meting.api` 发请求，超时由 `siteConfig.mdx.meting.timeout` 控制；客户端模式（默认）请求发生在浏览器。
- 接口地址、完整参数与返回类型见 `docs/developers/meting-api.md`。
- 本文的构建期示例只展示写法，不实际发起请求。
